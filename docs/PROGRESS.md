## 2. 단계별 수행 내용

### 2-1. 1차 기획 검토 (9/27)

외부 피드백을 문서와 한 줄씩 대조해 고쳤습니다.

| 문제 | 수정 |
|---|---|
| GFW 데이터를 "무료로 사업 가능"처럼 씀 | 비상업 조건, 상용화 시 라이선스 |
| 안전구역을 "입력받는다"와 "직접 계산한다"가 모순 | 입력만 받음 |
| 전 세계 발사 횟수를 시장 규모처럼 씀 | 해안 발사장 × 해상 통제 × 어업 × 구매 주체 |
| 발사일·보상액을 서비스가 정하는 것처럼 씀 | 비교와 근거만 제공 |
| 1인인데 4인 팀처럼 표기 | 1인 + 외부 자문 |

그리고 "고흥 앞바다가 위성 데이터에 실제로 보이는가"를 아무도 확인하지 않았다는 점을 발견해, **문서 수정보다 데이터 확인을 먼저** 했습니다.

### 2-2. 데이터 확인과 수집 (9/27)

1. GFW 지도에서 남해안 조업 분포 확인
2. 칸을 눌러 배 목록 확인 → 한국 어선, 고정어구·고정자망·선망 등 연안 어업
3. 과거 나로호 통제 규모(폭 24km, 길이 75km)를 참고해 **가정 통제구역**(24×78km, 1,869km²) 제작
4. 구역 안 배별·날짜별·칸별 조업 자료를 연도별로 다운로드 (2022~2025)

**시행착오:** 다운로드 옵션 차이로 위치가 빠진 파일, 1년이 한 줄로 합쳐진 파일이 섞여 세 번 다시 받음. 잘못된 파일은 코드가 바로 알려 주도록 형식 검사 추가.

### 2-3. 분석 (9/27~28)

| 질문 | 답 |
|---|---|
| 데이터가 충분한가? | 연 12~14만 시간, 860~960척, 4년간 1,568척 중 1,550척이 한국 어선 → **충분** |
| 날짜에 따라 영향이 다른가? | 4년 모두 2월·7월이 가장 적고 가을이 많음 → **다름** |
| 요일이 중요한가? | 해마다 패턴이 달라 → **기준에서 제외** |
| 실제 발사일에 조업이 줄었나? | 하루 단위로는 뚜렷하지 않음 (2차 오히려 높음, 3차 낮은 편, 4차 차이 없음) |

### 2-4. 데모 개발 (9/28)

Python + Streamlit으로 실제 데이터를 쓰는 화면 4개를 만들었습니다.

| 화면 | 내용 |
|---|---|
| ① 해역 조업 지도 | 바다를 약 9×11km 칸으로 나눠 조업 밀도, 월별·연도별 추이 |
| ② 선택지 비교 | 날짜와 구역 대안을 넣으면 예상 영향 순위 |
| ③ 영향근거 리포트 | 영향 배 수, 조업기회, 어구, 자주 오는 어선, 한계, 내려받기 |
| ④ 과거 발사일 확인 | 누리호 발사일 조업 vs 다른 해 같은 시기 |

**핵심 계산 예:** 2027-02-10이면 과거 4년의 1/26~2/25 하루 조업 중앙값(약 128시간) × 통제 4시간/24 ≈ **21시간**

**검증:** 연도별 합계가 GFW 화면과 같음, 화면 4개 자동 테스트 통과

### 2-5. 2차 기획 검토와 문서 단순화 (9/28)

| 발견한 문제 | 수정 |
|---|---|
| "최대 84% 차이"가 2월 vs 9월 비교라서, 발사창 안 며칠 중 고르는 실제 상황과 맞지 않음 | 사용 상황을 A(연간 계획)·B(예비일)·C(구역 지정)로 나눔. 숫자도 시기 효과(약 3.5배)와 구역 효과(17~44%)로 분리 |
| 기준선(±15일 중앙값)은 붙어 있는 날짜를 구분 못 함 | ② 예측 모델의 목적을 "예비일 비교"로 명확히 함 |
| 고정자망·정치망은 그물 철거 기간이 있어 "통제 시간 × 조업"으로는 과소 계산 | 어구별 영향 계산 추가 (인터뷰로 확인할 가정) |
| 통제구역이 발사장 앞바다 하나뿐 | 누리호 낙하 예상구역도 1주차에 확보 |
| 금액이 4주차에 처음 나와 사업성 판단이 늦음 | 1주차에 대략 추정 |
| 돈 내는 쪽(발사기업)과 믿어야 하는 쪽(어민)이 달라 중립성 의문 | 신뢰 원칙 추가: 코드 공개, 공동 발주, 금액은 범위로 |
| 어민에게 먼저 공개한다면서 데모에 어민용 화면 없음 | 어민용 1쪽 요약을 4주차 할 일로 추가 |
| 인터뷰가 전부 "예정" | 1주차에 1건 이상 |
| 누리호 발사를 문서마다 3건/4건으로 다르게 씀 | 하루 단위 확인은 2~4차 3건, 시간 단위 분석은 1~4차 4건으로 통일 |
| 문서가 너무 복잡함 | 4개 문서 모두 쉬운 말로 다시 씀, README에 읽는 순서 추가 |

## 3. 의사결정 기록

| 결정 | 이유 |
|---|---|
| 문서보다 데이터 확인을 먼저 | 기획 전체의 전제가 "위성으로 그 바다가 보인다"였기 때문 |
| 가정 통제구역 사용 | 실제 좌표 확보 전에도 분석을 시작하려고 |
| 요일을 기준선에서 제외 | 해마다 패턴이 달라 오히려 오차를 키움 |
| 손실 산정 대신 영향 비교 | 하루 단위로 발사 효과가 안 보였고, 어민은 다른 시간·해역으로 옮길 수 있음 |
| 안전구역 설계 기능 제거 | 발사체 제원이 비공개이고, 안전 기준은 어업 때문에 바꿀 수 없음 |
| 배 유형으로 거르지 않고 전체 합계 사용 | 다운로드마다 분류가 달라 거르면 연도 비교가 틀어짐 |
| 기술은 3가지로 한정 | 실제 약점(측정 불가, 날씨, 누락 선박)을 하나씩 메우는 것만 |
| 사용 상황을 A·B·C로 나눔 | 상황마다 고를 수 있는 폭이 달라, 한 숫자로 설명하면 과장이 됨 |
| 금액은 항상 범위로 | 단일 금액은 보상 상한처럼 쓰여 어민 신뢰를 잃을 수 있음 |

## 4. 틀렸던 것과 정정

| 무엇이 틀렸나 | 어떻게 고쳤나 |
|---|---|
| "3·4차 발사일에 발사장 쪽 조업이 0" | 비교 기준을 조업 있는 날만으로 계산해 평소 값을 부풀렸음. 조업 없는 날을 0으로 넣어 다시 계산하니 그 해역은 평소에도 대부분 0 → 주장 철회 |
| 4차 발사 날짜 | 한국시간 새벽 발사라 UTC 날짜로는 전날(11/26) → 수정 |
| 다운로드 형식 혼재 | 재수집, 형식 검사 코드 추가 |
| 배 분류 불일치 | 전체 합계 사용, API로 통일 예정 |
| "최대 84% 차이"를 대표 숫자로 씀 | 시기 효과(약 3.5배)와 구역 효과(17~44%, 가정 대안)로 나눠 표시 |

정정 과정을 남기는 이유: 심사에서 "숫자를 어떻게 믿나?"라는 질문에 검증 과정 자체를 보여줄 수 있습니다.

## 6. 중간 발표 구성안 (7장)

| # | 제목 | 내용 |
|:---:|---|---|
| 1 | 문제 | 2026년 제도 변화로 민간 발사기업이 어업 보상 책임. 나로호 때는 보상 근거가 애매해 미뤄졌고 [3], 셰틀랜드는 20개월 넘게 합의 실패 [4] |
| 2 | 아이디어 | 안전이 확인된 선택지 중 어업 피해가 작은 것을 위성 데이터로 비교, 같은 근거로 협의. 하지 않는 일(안전구역·발사일·보상액)도 함께 |
| 3 | 언제 쓰나 | 상황 A(연간 계획)·B(예비일)·C(구역 지정) 표 |
| 4 | 가능성 확인 | 가정 통제구역에서 연 12~14만 시간, 약 900척 조업 (지도 캡처) |
| 5 | 핵심 결과 | 시기 효과 약 3.5배(2월 vs 9월), 구역 효과 17~44% (비교 화면 캡처, 가정 대안임을 표시) |
| 6 | 발견한 한계와 정정 | 하루 단위로는 발사 영향이 안 보임 → 영향 비교로 범위 조정. 틀렸던 주장 철회 과정 |
| 7 | 데모 + 다음 계획 | 화면 4개 시연, 기술 3가지·금액·인터뷰 일정 |

**예상 질문과 답**

- **"그냥 평균 낸 거 아닌가요?"** → 지금은 기준선이 맞습니다. 비교 기준을 먼저 세웠고, 날씨 반영 모델은 이 기준선보다 나을 때만 씁니다.
- **"발사일은 궤도가 정하는데 2월과 9월 중에 고를 수 있나요?"** → 누리호 같은 정부 발사는 어렵습니다. 그래서 상황을 나눴습니다. 월 단위 비교는 일정이 유연한 민간 시험 발사(A)용이고, 발사창 안 예비일(B)은 날씨 예측으로 비교합니다.
- **"손실은 왜 계산 안 하나요?"** → 실제 발사일 자료로 확인해 보니 하루 단위로는 측정되지 않았고, 어민이 다른 시간·해역으로 옮길 수 있습니다. 시간 단위로 먼저 측정 가능성을 확인합니다.
- **"AIS 없는 작은 배는요?"** → 등록 어선 수와 비교해 포착률을 계산하고 SAR로 검증합니다. 리포트에 한계를 적습니다.
- **"발사기업이 돈을 내는데 어민이 믿을까요?"** → 계산 방법과 코드를 공개하고, 공동 발주를 기본으로 하며, 금액은 범위로만 냅니다.
- **"통제구역은 진짜인가요?"** → 지금은 과거 규모를 참고한 가정값이고, 1주차에 실제 항행경보 좌표(낙하구역 포함)로 바꿉니다.
