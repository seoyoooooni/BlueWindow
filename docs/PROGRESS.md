## 2. 단계별 수행 내용

### 2-1. 기획서 검토

**한 일:** 외부 피드백 7가지를 실제 문서와 한 줄씩 대조했습니다.

**확인된 문제**
- GFW 데이터를 "무료로 사업 가능"처럼 표현 (실제는 비상업 조건)
- 안전구역을 "입력받는다"와 "직접 계산한다"가 문서 간에 모순
- 전 세계 발사 횟수를 시장 규모처럼 사용
- 발사일·안전구역·보상액을 서비스가 정하는 것처럼 표현
- 1인 참가인데 4인 팀처럼 표기

**추가로 찾은 문제:** "고흥 앞바다에 위성 데이터가 실제로 있는가"를 아무도 확인하지 않았음 → 기획 전체의 전제라서 **문서 수정보다 데이터 확인을 먼저** 하기로 결정

### 2-2. 데이터 확인과 수집

**한 일**
1. Global Fishing Watch(GFW) 지도에서 남해안 조업 분포 확인
2. 격자를 클릭해 선박 목록 확인 → 한국 선적, 고정어구·고정자망·선망 등 연안 어업
3. 과거 나로호 통제 규모(폭 24km, 길이 75km)를 참고해 나로우주센터 남쪽에 **가정 통제구역**(24×78km, 1,869km²) 제작·업로드
4. 구역 안 선박별·일별·격자별 조업 자료를 연도별로 다운로드 (2022~2025)

**용어**
- AIS: 선박이 자기 위치를 송신하는 신호. 위성이 수신
- GFW: AIS를 모아 조업 여부를 추정해 공개하는 국제 비영리 단체
- SAR: 구름·밤과 관계없이 촬영하는 레이더 위성 영상. AIS를 끈 배도 보이지만 촬영 시점에만 존재

**시행착오:** 다운로드 옵션 차이로 위치(위경도)가 빠진 파일, 1년이 한 줄로 합쳐진 파일이 섞여 세 차례 재수집. 최종적으로 4년 모두 "격자·선박·일 단위" 자료 확보. 코드에 형식 검사를 넣어 잘못된 파일은 바로 알려주게 함.

### 2-3. 분석

| 질문 | 결과 |
|---|---|
| 데이터가 충분한가? | 연 12~14만 시간, 860~960척, 4년간 1,568척 중 1,550척이 한국 선적 → **충분** |
| 날짜에 따라 영향이 다른가? | 4년 모두 2월·7월이 가장 적고 가을이 많음 → **다름** |
| 요일이 중요한가? | 해마다 패턴이 달라 → **기준에서 제외** |
| 실제 발사일에 조업이 줄었나? | 일 단위로는 뚜렷하지 않음 (2차 오히려 높음, 3차 낮은 편, 4차 차이 없음) |

### 2-4. 데모 개발

Python + Streamlit으로 실제 데이터를 쓰는 웹 화면 4개를 만들었습니다.

| 화면 | 내용 |
|---|---|
| ① 해역 조업 지도 | 바다를 약 9×11km 칸으로 나눠 조업 밀도 표시, 월별·연도별 추이 |
| ② 후보일 비교 | 후보 날짜와 통제구역 대안을 넣으면 예상 영향 순위 |
| ③ 영향근거 리포트 | 영향 선박 수, 조업기회, 어구, 정기 조업 선박 목록, 데이터 한계, 파일 내려받기 |
| ④ 과거 발사일 확인 | 누리호 발사일 조업과 다른 해 같은 시기 비교 |

**핵심 계산 (기준선):** 후보일이 2027-02-10이면 과거 4년의 1/26~2/25 기록을 모아 하루 조업의 중앙값(약 128시간)을 구하고, 통제 4시간이면 128 × 4/24 ≈ **21시간**을 "영향받는 조업기회"로 봅니다.

**결과 예시 (통제 4시간)**

| 후보일 | 구역 A (기본) | 구역 B (연안 제외) | 구역 C (남쪽 축소) |
|---|---:|---:|---:|
| 2027-02-10 | 21시간 | **12시간** | 21시간 |
| 2027-05-12 | 63시간 | 45시간 | 55시간 |
| 2027-09-15 | 76시간 | 63시간 | 70시간 |

**검증:** 연도별 합계가 GFW 화면 수치와 일치, 화면 4개 자동 테스트 통과(pandas 2·3 모두)

### 2-5. 문서 개편

| 항목 | 전 | 후 |
|---|---|---|
| 서비스 역할 | 안전구역 설계 + 발사일 추천 + 보상 정산 | 안전성이 확인된 후보들의 어업영향 비교 |
| 결과물 | 보상액 | 영향 규모와 근거 리포트 (보상은 참고 범위만, 2단계) |
| 데이터 이용 | 무료로 사업 가능 | 검증은 비상업 조건, 상용화 시 라이선스 |
| SAR | AIS 끈 배까지 확인 | 촬영 시점 표본으로 편향 점검 |
| 시장 | 전 세계 발사 324회 | 해안 발사장 × 해상 통제 × 어업 × 구매 주체 |
| 수익 | 발사장 연간 구독 | 용역 → 건별 리포트 → 연간 계약 → 해상풍력 등 확장 |
| 팀 | 4인 | 1인 + 외부 자문 |
| 제외 | - | 낙하물 몬테카를로 모델, 어민 앱 |

## 3. 의사결정 기록

| 결정 | 이유 |
|---|---|
| 문서보다 데이터 확인을 먼저 | 기획 전체의 전제가 "위성으로 그 바다가 보인다"였기 때문 |
| 가정 통제구역 사용 | 실제 좌표 확보 전에도 분석을 시작하려고. 과거 통제 규모를 참고해 크기를 맞춤 |
| 요일을 기준선에서 제외 | 해마다 패턴이 달라 오히려 오차를 키움 |
| 손실 산정 대신 영향 비교 | 일 단위 자료로 발사 효과가 측정되지 않았고, 어민은 다른 시간·해역으로 옮겨 조업할 수 있음 |
| 안전구역 설계 기능 제거 | 발사체 제원이 비공개라 신뢰할 수 없고, 안전 기준을 어업 때문에 바꿀 수 없음 |
| 선박 유형으로 거르지 않고 전체 합계 사용 | 다운로드마다 분류가 달라 거르면 연도 비교가 틀어짐. 합계는 GFW 화면과 일치 |
| 고도화 기술은 3축으로 한정 | 서비스의 실제 약점(측정 불가, 날씨, 누락 선박)을 하나씩 메우는 것만 선택 |

## 4. 시행착오와 정정

| 무엇이 틀렸나 | 어떻게 발견·정정했나 |
|---|---|
| "3·4차 발사일에 발사장 쪽 조업이 0" | 비교 기준을 조업 있는 날만으로 계산해 평소 값을 부풀렸음. 조업 없는 날을 0으로 포함해 재계산하니 그 해역은 평소에도 대부분 0 → 주장 철회 |
| 4차 발사 날짜 | 한국시간 새벽 발사라 UTC 날짜로는 전날(11/26) → 기준 날짜 수정 |
| 다운로드 형식 혼재 | 위치 없는 파일, 1년 합계 파일 발견 → 재수집, 형식 검사 코드 추가 |
| 선박 분류 불일치 | 2022 파일은 세부 어구, 2023~25 파일은 미분류·비어선이 많음 → 전체 합계 사용, API로 통일 예정 |

정정 과정을 기록해 두는 이유: 심사에서 "숫자를 어떻게 믿나?"에 대해 검증 과정 자체를 보여줄 수 있습니다.

**예상 질문과 답**
- "그냥 평균 낸 거 아닌가요?" → 현재는 기준선이 맞습니다. 다음 단계에서 기상 반영 예측 모델을 만들고, 기준선보다 나을 때만 바꿉니다. 비교 기준을 먼저 세운 것입니다.
- "손실은 왜 계산 안 하나요?" → 실제 발사일 데이터로 확인해 보니 일 단위로는 측정되지 않았고, 어민이 다른 시간·해역으로 옮길 수 있습니다. 시간 단위 인과추론으로 먼저 측정 가능성을 검증합니다.
- "AIS 없는 작은 배는요?" → 맞는 지적입니다. SAR 위성 탐지와 교차해 포착률을 추정하고 보정할 예정이며, 리포트에 한계를 명시합니다.
- "통제구역은 진짜인가요?" → 현재는 과거 규모를 참고한 가정값이고, 1주차에 실제 항행경보 좌표로 교체합니다.
