## 1. 목표와 원칙

**목표:** 나로우주센터 주변 바다에서, 안전이 확인된 발사 선택지(날짜·통제구역)의 어업 영향을 위성 데이터로 비교하고 협의용 리포트로 만든다.

**원칙**

1. 안전구역·발사일·보상액은 정하지 않는다. 주어진 선택지만 비교한다.
2. 모든 결과에 **범위(불확실성)와 데이터 한계**를 함께 보여 준다.
3. 새 모델은 **지금 기준선보다 나을 때만** 바꾼다. 못하면 "시험했지만 쓰지 않음"으로 보고한다.

**주요 날짜**

| 날짜 | 일정 |
|---|---|
| 11/5 | 참가 신청·제출 마감 |
| 11/11 | 예선 심사 |
| 11/25~26 | 본선 (경상국립대, 이틀) |

| 기능 | 계산 | 파일 |
|---|---|---|

| 날짜 | 구역 A (기본) | 구역 B (연안 제외) | 구역 C (남쪽 축소) |
|---|---:|---:|---:|
| 2027-02-10 | 21시간 | **12시간** | 21시간 |
| 2027-05-12 | 63시간 | 45시간 | 55시간 |
| 2027-09-15 | 76시간 | 63시간 | 70시간 |

- 시기 효과: 같은 구역 A에서 2월 vs 9월 약 3.5배
- 구역 효과: 같은 날 구역 대안별 17~44% (B·C는 가정 대안)

**지금 계산의 한계와 해결**

| 한계 | 해결 |
|---|---|

## 4. 추가할 기능 설명

### 금액 추정

- 시간당 어업가치 ≈ 해당 해역·월 생산금액(KOSIS, 수협 위판) ÷ 같은 기간 조업시간
- 결과: "통제 1회 영향 약 ○~○만 원, 선택에 따라 ○만 원 차이"
- **보상액이 아닌 참고 규모.** 항상 범위로, 대체 조업 반영 전·후 함께 표시
- 영향이 작게 나오면: 보상액보다 **협의 지연·갈등 비용**이 크다는 논리로 사업성을 설명

### ① 발사 영향 측정 (시간 단위 인과추론)

**질문:** 통제 시간 동안 조업이 실제로 얼마나 줄었고, 줄어든 조업은 어디로 갔나?

**쉽게 말하면:** 발사한 날 통제구역의 조업을 "발사가 없었다면 어땠을지"와 비교한다. "발사가 없었다면"은 발사 영향을 받지 않는 먼 바다 여러 곳을 섞어서 만든다.

| 방법 | 내용 |
|---|---|
| 합성 통제 | 발사 전 기간에 통제구역의 시간별 조업을 가장 잘 따라 하도록, 먼 남해 칸 20~40개에 가중치(0 이상, 합 1)를 준다. 통제 시간대에 이 가중합과 실제 조업의 차이 = 효과 |
| 가짜 발사일 검정 | 발사 없는 날·다른 해역에 같은 계산을 반복해 "우연히 나오는 효과" 분포를 만들고, 실제 효과가 얼마나 극단인지 본다 (p값) |
| 이벤트 스터디 회귀 | 조업시간(칸, 시각) = 칸 고정효과 + 요일×시각 고정효과 + Σ β_k·[발사 후 k시간 × 통제구역] + Σ γ_k·[발사 후 k시간 × 바로 옆 해역] + 오차. β는 통제구역 효과, γ는 **옆으로 밀려난 조업** |
| 배별 추적 | 발사 전 2주간 통제구역에서 조업한 배가 발사 당일 (1) 옆 해역에서 조업 (2) 다른 시간에 조업 (3) 조업 안 함 중 어디에 해당하는지 → **대체율** |

- 대상: 누리호 1차(2021-10-21), 2차(2022-06-21), 3차(2023-05-25), 4차(2025-11-27 KST, UTC로는 11-26)
- 발사가 4건뿐이라 발사별 결과를 따로 보여 준다. 바로 옆 해역을 비교 대상으로 쓰면 옮겨 간 조업 때문에 효과가 부풀려지므로 먼 해역을 쓴다.
- 효과가 뚜렷하지 않으면 그대로 보고한다. 그 자체가 "손실 산정 대신 영향 비교"라는 설계의 근거다.
- 결과 예: "통제 시간 조업 ○% 감소, 그중 ○%는 인근으로 이동" 그래프

### ② 예비일 예측 (날씨 반영)

**질문:** 발사창 안 며칠짜리 후보들 가운데 어느 날 조업이 적을지, 날씨까지 반영해 맞힐 수 있나?

**왜:** 기준선은 ±15일 중앙값이라 붙어 있는 날짜들은 거의 같은 값이 나온다. 며칠 차이는 계절이 아니라 **날씨**가 좌우한다.

| 항목 | 내용 |
|---|---|
| 모델 | LightGBM 분위수 회귀 (10·50·90%) → "적으면·보통·많으면" 범위 |
| 입력 | 날짜(계절), 명절 전후, 풍속·파고(ERA5), 작년 같은 시기 조업, 최근 조업 |
| 시험 | 2022~23 학습 → 2024 시험, 2022~24 학습 → 2025 시험 |
| 채택 기준 | ±3일 안의 후보 3~5개 순위를 기준선보다 잘 맞힐 때만 (스피어만 상관, 분위수 손실) |

### ③ 누락 선박 보정 (SAR)

**질문:** AIS에 안 잡히는 배가 얼마나 되고, 그만큼 영향이 작게 계산되고 있나?

| 단계 | 내용 |
|---|---|
| 1차 | 인근 등록 어선 수 vs 위성 AIS에 잡힌 배 수 → 대략적인 포착률 |
| 기본 | GFW SAR 탐지에서 AIS와 매칭된 배 / 안 된 배 → 포착률 (신뢰구간 포함). 보정 영향 = 조업기회 ÷ 포착률 |
| 심화 | Sentinel-1 원본 영상에서 직접 배 탐지 (육지 가리기 → 주변보다 밝은 점 찾기(CFAR) → GFW 결과와 비교) |

한계: Sentinel-1은 약 15m 미만 작은 배를 잘 못 잡고 위성이 지나갈 때만 찍으므로, 보정값은 **최소치**다.

### 어민용 1쪽 요약

- 통제 날짜·시간, 구역 지도, "평소 이 시기 이 구역에서 조업하는 배 약 ○척"
- 쉬운 말, 숫자 3개 이내, 데이터 한계 한 줄
- 어촌계 공지용으로 인쇄할 수 있는 형태

## 6. 시스템 구조와 폴더

```
[모으기]  GFW CSV/API · ERA5 · 항행경보 · 생산 통계
             ↓  ingest/  (data/raw → data/processed/*.parquet)
[다듬기]  배 분류 통일, 칸 통일
             ↓
[분석]    core.py 기준선 ─┬─ causal/   ① 발사 영향 측정
                          ├─ forecast/ ② 예비일 예측
                          └─ sar/      ③ 누락 보정
             ↓
[화면]    streamlit_app.py  ① 지도 ② 비교 ③ 리포트 ④ 발사 영향
```

- 무거운 계산은 미리 돌려 결과 파일로 저장하고, 화면은 그 파일만 읽는다.
- 계산과 화면을 분리해 계산만 따로 테스트할 수 있게 한다.

```
oceanclear/
├─ README.md · requirements.txt · .env.example
├─ docs/       PROPOSAL.md · DEV_PLAN.md · PROGRESS.md
├─ data/       2022~2025/, naro_control_zone_approx.geojson, raw/·processed/ (예정)
├─ ingest/     gfw_api.py, notices.py, era5.py (예정)
├─ causal/     synth.py, event_study.py, displacement.py (예정)
├─ forecast/   features.py, model.py, backtest.py (예정)
├─ sar/        capture_rate.py, cfar.py (예정)
├─ analysis/   summarize_gfw.py, results_2022_2025.md
└─ app/        core.py, streamlit_app.py
```

**기술 스택:** Python 3.10+, pandas, pyarrow, requests, shapely, geopandas, NumPy, SciPy, statsmodels, Streamlit, Plotly / (필요 시) cdsapi, LightGBM, scikit-learn, rasterio, scikit-image

| 인터뷰 섭외 실패 | 문헌 [8][9]의 조업일수·어구 자료로 대신하고 한계 명시. 어촌계는 고흥군청 해양수산과를 통해 연락 시도 |
| 금액이 작게 나옴 | 협의 지연·갈등 비용 중심으로 사업성 설명, 해외 발사장 시장 강조 |

| 발사 4건으로 표본 부족 | 발사별 결과 병기, 가짜 발사일 검정, 결론을 약하게 |

| 시간 부족 | 6순위 → 5순위 순서로 뺀다. 1~3순위는 반드시 지킨다 |
