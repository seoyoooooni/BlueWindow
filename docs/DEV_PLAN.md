## 1. 목표와 결과물

**목표:** 바다를 잠시 막는 통제(우주발사, 사격훈련, 해상공사)가 어업에 주는 영향을 위성 선박 데이터로 계산하고, 선택지를 비교해 협의용 리포트로 만든다. 첫 적용 해역은 나로우주센터 앞바다다.

**원칙**

1. 안전구역·발사일·보상액은 정하지 않는다. 주어진 선택지만 비교한다.
2. 모든 결과에 **범위(불확실성)와 데이터 한계**를 함께 보여 준다.
3. 새 모델은 **지금 기준선보다 나을 때만** 바꾼다. 못하면 "시험했지만 쓰지 않음"으로 보고한다.
4. 모든 숫자는 저장소 코드로 **다시 계산할 수 있어야** 한다.

**최종 결과물**

| 결과물 | 내용 |
|---|---|
| 웹 데모 (배포) | 심사위원이 링크로 직접 눌러 보는 Streamlit 앱. 지도, 선택지 비교, 리포트, 과거 통제 확인, 통제 달력 |
| 리포트 2종 | 발사기업·발사장용 영향근거 리포트, 어민용 1쪽 요약 |
| 분석 결과 | 조업 기준선, 항행경보 통제 분석, 통제 영향 측정 결과 (표·그림) |
| 기획서 | 해커톤 제출 문서 ([PROPOSAL.md](PROPOSAL.md)) |
| 코드 | 수집 → 정리 → 분석 → 화면까지 재현 가능한 저장소 |

## 2. 전체 구조

```
[모으기]   GFW 조업(CSV·API) · 항행경보 · ERA5 날씨 · 생산 통계 · SAR 탐지
              │  ingest/
              ▼
[정리]     조업 표 (배 × 날짜/시각 × 0.1° 칸)      통제 이벤트 표 (구역 다각형 × 날짜 × 시간대 × 유형)
              │                                        │
              └──────────────┬─────────────────────────┘
                             ▼
[분석]     기준선·선택지 비교 (core)  ─┬─ ① 통제 영향 측정 (causal/)
                                     ├─ ② 예비일 예측 (forecast/)
                                     └─ ③ 누락 선박 보정 (sar/)
                             ▼
[결과]     영향근거 리포트 · 어민용 요약 · 해역 누적 영향
                             ▼
[화면]     Streamlit: ① 지도 ② 비교 ③ 리포트 ④ 과거 통제 ⑤ 통제 달력
```

- 무거운 계산(수집, 인과추론, 모델 학습)은 미리 돌려 결과 파일(parquet/CSV)로 저장하고, 화면은 그 파일만 읽는다.
- 계산(`app/core.py`, 분석 폴더)과 화면(`app/streamlit_app.py`)을 분리해 계산만 따로 테스트한다.

## 4. 모듈별 개발 내용

### 4-1. 수집 (`ingest/`)

| 파일 | 하는 일 |
|---|---|
| `gfw_csv.py` | 지도에서 받은 CSV 적재, 형식 검사 (일 단위가 아니거나 좌표가 없으면 오류) |
| `gfw_api.py` | 4Wings(시간 단위 조업), Events, Vessels API 호출. 요청을 기간·구역별로 나눠 받고 결과를 `data/raw/`에 캐시 |
| `notices.py` | 항행경보 목록·상세 수집. 이미 받은 문서는 건너뜀. 지금은 `data/notices/fetch_details.py` |
| `era5.py` | 해역 박스의 10m 바람, 유의파고 시간별 자료 |
| `stats.py` | KOSIS·수협 생산금액 정리 |

### 4-2. 해역 데이터 엔진 (`app/core.py`)

- **입력:** GFW 조업 CSV
- **처리:** 연도별 파일 합치기 → 조업 없는 날은 0으로 채운 일별 표 → 칸별·월별 밀도 → 같은 시기 2개 연도 이상 온 "자주 오는 어선"
- **출력:** 일별 조업 표, 칸별 밀도, 어선 목록
- **상태:** 작동

### 4-3. 통제 이벤트 엔진 (`analysis/parse_notices.py` → `app/notices.py`로 이동 예정)

- **입력:** 항행경보 상세 JSON
- **처리:**
  1. 좌표 문자열(`34-27-31N, 127-31-12E`)을 도 단위로 변환해 다각형 생성. 점 + 반경이면 원으로 변환
  2. 날짜·시간대 목록을 한 줄씩 펼침 (`20220615` × `12:00 ~ 19:20`). 자정을 넘는 시간대 처리
  3. 유형 분류: 군 사격, 해경 사격, 해상훈련, 해상작업, 국내 우주발사, 해외 발사 낙하구역, 기타
  4. 중복 제거(같은 구역·날짜·시작시각), 제목에 '취소'가 있는 문서 제외
- **출력:** `data/notices/events.csv` (구역 WKT, 날짜, 시작·종료, 시간, 면적, 유형)
- **개선할 점:** 변경·취소 문서를 원 문서와 연결(`ORG_D_ID`), 연기된 날 표시, 해역(격자)과 겹치는 비율 계산
- **상태:** 작동 (1차)

### 4-4. 영향 계산 (`app/core.py`)

| 계산 | 방법 |
|---|---|
| 기준선 | 후보 날짜 ±15일에 해당하는 과거 모든 해의 하루 조업시간 → 중앙값, 많은 날(75%) |
| 통제 중 조업기회 | 하루 조업시간 × (통제 시간 ÷ 24). 시간 단위 자료가 들어오면 실제 통제 시간대의 조업으로 교체 |
| 구역 겹침 | 통제 다각형과 0.1° 칸의 겹친 면적 비율로 칸별 조업을 나눠 합산 (지금은 칸 중심 기준) |
| 어구별 보정 | 이동식은 통제 시간만, 고정식은 어구 철거·재설치 기간(인터뷰로 확인할 값)까지 포함 |
| 선택지 비교 | 날짜 × 구역 대안별 조업기회를 정렬, 범위 함께 표시 |
| 해역 누적 영향 | 한 해 동안 해역에 걸린 모든 통제 이벤트의 조업기회 합계와 달력 |
| 금액 범위 | 시간당 어업가치 = 해역·월 생산금액 ÷ 같은 기간 조업시간. "통제 1회 약 ○~○원"을 대체 조업 반영 전·후로. **보상액 아님** |

### 4-5. ① 통제 영향 측정 (`causal/`)

**질문:** 통제 시간 동안 조업이 실제로 얼마나 줄었고, 줄어든 조업은 어디로 갔나?

**핵심 아이디어:** 발사는 4건뿐이지만, 같은 해역의 사격·훈련 통제는 연 100~340건이고 시각까지 기록돼 있다. 이 반복 통제로 먼저 효과를 추정하고, 누리호 4건은 그 결과와 비교해 검증한다.

| 방법 | 내용 |
|---|---|
| 이벤트 스터디 회귀 | 조업시간(칸, 시각) = 칸 고정효과 + 요일×시각 고정효과 + Σ β_k·[통제 후 k시간 × 통제구역] + Σ γ_k·[통제 후 k시간 × 바로 옆 해역] + 오차. β는 통제구역 효과, γ는 **옆으로 밀려난 조업**. 사격 통제 수백 건으로 추정 |
| 합성 통제 | 통제 전 기간에 통제구역의 시간별 조업을 가장 잘 따라 하도록, 먼 남해 칸 20~40개에 가중치(0 이상, 합 1)를 준다. 통제 시간대에 가중합과 실제의 차이 = 효과. 누리호 4건에 개별 적용 |
| 가짜 통제일 검정 | 통제 없는 날·다른 해역에 같은 계산을 반복해 "우연히 나오는 효과" 분포를 만들고 실제 효과가 얼마나 극단인지 본다 |
| 배별 추적 | 통제 전 2주간 통제구역에서 조업한 배가 통제 당일 (1) 옆 해역에서 조업 (2) 다른 시간에 조업 (3) 조업 안 함 중 어디에 해당하는지 → **대체율** |

- 바로 옆 해역을 비교 대상으로 쓰면 옮겨 간 조업 때문에 효과가 부풀려지므로 먼 해역을 쓴다.
- 효과가 뚜렷하지 않으면 그대로 보고한다. 그 자체가 "손실 산정 대신 영향 비교"라는 설계의 근거다.
- **도구:** statsmodels(고정효과 회귀), SciPy(가중치 최적화), NumPy
- **출력:** "통제 시간 조업 ○% 감소, 그중 ○%는 인근으로 이동" 그래프와 표

### 4-6. ② 예비일 예측 (`forecast/`)

**질문:** 발사창 안 며칠짜리 후보들 가운데 어느 날 조업이 적을지, 날씨까지 반영해 맞힐 수 있나?

| 항목 | 내용 |
|---|---|
| 모델 | LightGBM 분위수 회귀 (10·50·90%) → "적으면·보통·많으면" 범위 |
| 입력 | 날짜(계절), 명절 전후, 풍속·파고(ERA5), 작년 같은 시기 조업, 최근 조업, 그날 걸린 다른 통제 |
| 시험 | 2022~23 학습 → 2024 시험, 2022~24 학습 → 2025 시험 |
| 채택 기준 | ±3일 안의 후보 3~5개 순위를 기준선보다 잘 맞힐 때만 (스피어만 상관, 분위수 손실) |

### 4-7. ③ 누락 선박 보정 (`sar/`)

| 단계 | 내용 |
|---|---|
| 1차 | 인근 등록 어선 수 vs 위성 AIS에 잡힌 배 수 → 대략적인 포착률 |
| 기본 | GFW SAR 탐지에서 AIS와 매칭된 배 / 안 된 배 → 포착률 (신뢰구간 포함). 보정 영향 = 조업기회 ÷ 포착률 |
| 심화 (선택) | Sentinel-1 또는 KOMPSAT-5 원본 영상에서 직접 배 탐지 (육지 가리기 → 주변보다 밝은 점 찾기(CFAR) → GFW 결과와 비교) |

한계: Sentinel-1은 약 15m 미만 작은 배를 잘 못 잡고 위성이 지나갈 때만 찍으므로 보정값은 **최소치**다.

| ③ 영향근거 리포트 | 수치, 어구, 자주 오는 어선, 한계, 내려받기 | 작동 |

| ⑤ 해역 통제 달력 | 항행경보 통제를 지도·달력으로, 통제마다 조업기회, 연간 누적 | 예정 |
| 어민용 요약 | 1쪽 요약 미리보기·인쇄 | 예정 |

- 지도는 Plotly `Scattermap`, 표는 `st.dataframe`
- **배포:** Streamlit Community Cloud. 결과 파일만 올리고 원자료는 올리지 않는다.

## 7. 검증 원칙과 테스트

| 대상 | 확인 | 상태 |
|---|---|:---:|
| GFW 적재 | 연도별 합계가 GFW 화면과 같음 | ✅ |
| 날짜 형식 | 하루 단위가 아닌 파일은 오류 표시 | ✅ |
| 0 채우기 | 조업 없는 날도 기준선에 포함 | ✅ |
| 화면 | 4개 화면 오류 없음 | ✅ |
| 항행경보 파싱 | 누리호 2차 구역·시각이 상황판 표시와 같음 (1,719km², 12:00~19:20) | ✅ |
| 항행경보 중복 | 같은 구역·날짜·시각이 한 번만 세어짐 | ✅ |
| 합성 통제 | 가짜 효과를 심은 모의 자료에서 그 효과를 되찾는지 | 예정 |
| 가짜 통제일 | 통제 없는 날 효과가 0 근처인지 | 예정 |
| 예측 모델 | 시험 연도에서 기준선보다 나은지 | 예정 |
| 배포 | 배포 링크에서 모든 화면이 열리는지 | 예정 |

틀린 결과를 발견하면 고치고 개발 과정 문서에 **무엇이 왜 틀렸는지** 남긴다.

## 10. 알려진 문제와 대응

| 문제 | 대응 |
|---|---|
| GFW 다운로드마다 배 분류가 다름 (2022: 세부 어구 / 2023~25: 미분류 많음) | 지금은 전체 합계 사용(GFW 화면과 일치), Vessels API로 통일 |
| GFW 자료가 가정 구역(24×78km)만 있음. 실제 누리호 구역·사격 구역은 더 넓음 | 남해 동부로 범위를 넓혀 다시 받기 |
| 항행경보는 공지 기준 (연기·취소가 섞임) | 변경 문서 연결, 연기된 날 표시, "공지 기준" 명시 |
| 항행경보 유형 분류가 제목 기반이라 연도별로 흔들림 (예: 해경 사격) | 발행 기관 코드(`GOV_CD`)·문서 종류로 보강, 사격은 합쳐서 보고 |
| AIS 없는 작은 배 누락 | 포착률 보정, 리포트에 한계 명시 |
| 인터뷰 섭외 실패 | 문헌의 조업일수·어구 자료로 대신하고 한계 명시. 고흥군청 해양수산과 통해 연락 |
| 금액이 작게 나옴 | 협의 지연·갈등 비용과 누적 영향 중심으로 사업성 설명 |
