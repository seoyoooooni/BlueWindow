# 블루윈도우 (Blue Window)

> **로켓 발사부터 사격훈련까지, 바다를 잠시 막아야 할 때 어업 피해가 가장 작은 선택지를 위성 데이터로 찾아 주는 서비스**
> 부제: 위성 선박 데이터 기반 해상 통제 영향 관리 플랫폼 (첫 적용: 우주발사장 해역)

2026 스페이스 해커톤 · 부문 2. 위성활용 비즈니스 모델

---

## 요약

| | |
|---|---|
| **문제** | 2026년 제도가 바뀌어 민간 발사기업이 **어업 피해 보상** 책임을 지게 됐다. 그런데 발사 전에 "어떤 선택이 어업 피해가 작은지" 비교할 자료가 없다. |
| **해결** | 위성이 기록한 어선 조업 데이터를 이용해, 안전이 이미 확인된 발사 선택지(날짜·통제구역)별로 어업 영향을 비교하고 협의용 리포트를 만든다. |
| **증거** | 나로우주센터 앞바다에서 연 12~14만 시간, 약 900척의 조업을 위성으로 확인했다. 같은 구역이라도 2월 발사와 9월 발사는 영향이 **약 3.5배** 차이 난다. |
| **규모** | 항행경보를 분석하니 전국 해상 통제가 **연 6,900~8,300건**이다(2022~2025). 같은 나로 해역에서도 우주발사 통제는 연 2~6건이지만 사격·해상훈련 통제는 **연 100~340건** 겹친다. 같은 엔진으로 모든 통제를 분석한다. |

## 하는 일과 하지 않는 일

| 하는 일 | 하지 않는 일 |
|---|---|
| 주어진 선택지들의 **어업 영향 비교** | 안전구역 설계 (안전 기준은 발사장이 정함) |
| 협의용 **근거 리포트** 작성 | 발사일 결정 (궤도·발사체 준비가 먼저 정함) |
| 어민에게 통제 일정과 영향을 **미리 공개** | 보상액 결정 (기존 협의 절차에서 정함) |

## 언제 쓸까

선택지가 실제로 얼마나 넓은지는 상황마다 다르다. 그래서 상황별로 쓰는 방법이 다르다.

| 상황 | 누가 | 고를 수 있는 것 | 블루윈도우가 쓰는 방법 |
|:---:|---|---|---|
| **A. 연간 발사 계획** | 민간 발사기업 (시험 발사처럼 일정이 비교적 유연할 때) | 어느 달·분기에 쏠지 | 과거 같은 시기 조업 기준선 (지금 작동) |
| **B. 예비일 고르기** | 발사운영팀 | 발사창 안의 며칠 | 날씨를 반영한 예측 모델 (개발 예정) |
| **C. 안전구역 지정** | 우주항공청 | 구역 모양·범위 대안 | 구역 대안별 비교 (지금 작동, 실제 대안 필요) |
| **D. 반복 통제 관리** | 해군·해경·지자체·수협 | 사격훈련 등 반복 통제의 시기·구역 | 항행경보 자동 수집 → 통제마다 영향 계산, 누적 영향 지도 (개발 예정) |

## 데모 실행

```bash
git clone <저장소 주소>
cd bluewindow
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run app/streamlit_app.py
```

화면: ① 해역 조업 지도 ② 후보 비교 ③ 영향근거 리포트 ④ 과거 발사일 확인

데이터는 GFW 지도에서 내려받은 CSV를 `data/<연도>/`에 넣는다 ([개발 계획](docs/DEV_PLAN.md#3-데이터)).

## 폴더 구조

```
bluewindow/
├─ docs/        # 기획서, 개발 계획, progress/ (주간 발표)
├─ data/        # GFW CSV (연도별), 통제구역 GeoJSON, notices/ (항행경보)
├─ analysis/    # 분석 스크립트와 결과
├─ app/         # core.py (계산), streamlit_app.py (화면)
└─ requirements.txt
```
